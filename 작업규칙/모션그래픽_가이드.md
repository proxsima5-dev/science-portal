# 모션 그래픽 가이드 (수업자료·시뮬레이션 공통)

수업자료 HTML과 시뮬레이션에서 **움직임으로 이해를 돕는 것**을 최대한 활용한다. 학생은 앞에서 배운 것도 잊고 오고, 설명이 빠르면 따라오지 못한다. 글과 정지 그림으로 설명하던 것을 움직임으로 보여 주는 것이 목적이다.

- 초안을 쓰는 쪽(Claude나 다른 AI): 초안을 짤 때 쪽마다 "무엇이 어떻게 움직여야 이해되는가"를 먼저 생각하고 `모션` 항목에 적는다.
- Claude Code: 초안의 `모션`을 구현한다. 초안에 없어도 움직임이 이해를 크게 돕는 곳은 보고서에 제안하고, 승인받은 뒤 넣는다.

## 1. 움직임을 넣는 기준

넣는다:
- 눈에 안 보이는 것을 보여 줄 때: 입자 운동, 힘의 방향, 빛의 경로, 공전·자전, 온도·압력에 따른 변화
- 원인 → 결과의 순서가 중요할 때: 압력을 올리면 → 입자가 더 자주 부딪힌다 → 부피가 줄어든다
- 크기 변화의 감을 줄 때: 부피 = 가로 × 세로 × 높이가 커지는 장면
- 한 번에 보여 주면 복잡한 것을 단계별로 쌓아 올릴 때(빌드업)
- 학생이 예측한 것과 실제를 비교할 때(예측 → 재생 → 확인)

넣지 않는다:
- 장식용 움직임: 글자가 날아 들어오거나 도형이 튀는 효과. 읽는 데 방해가 된다.
- 글을 읽어야 하는 쪽에서 계속 도는 움직임. 학생 시선을 빼앗는다.
- 정지 그림으로 충분한 곳. 모든 쪽에 억지로 넣지 않는다.

판단 질문: "이 움직임을 빼면 학생이 이해를 못 하는가?" 아니라면 뺀다.

## 2. 움직임 종류와 쓰임

| 종류 | 쓰임 | 예 |
|---|---|---|
| 입자 애니메이션 | 기체·액체·고체의 입자 운동, 온도·압력·부피 변화 | 온도를 올리면 입자가 빨라지고 벽에 더 세게 부딪힌다 |
| 벡터(화살표) 애니메이션 | 힘의 방향·크기, 합력, 속도 | 힘이 커지면 화살표가 길어진다 |
| 궤도·운동 | 공전·자전, 달의 위상, 물체의 낙하·운동 | 지구가 공전하며 계절 위치가 바뀐다 |
| 빛·파동 | 빛의 직진·반사·굴절, 그림자 | 광원을 옮기면 그림자 길이가 변한다 |
| 변화 전후 비교 | 두 상태를 나란히 두고 한쪽만 움직임 | 실제 / 이상(교과서 상황) 토글 |
| 단계별 빌드업 | 설명을 한 조각씩 쌓기 | 클릭할 때마다 한 단계씩 나타난다 |
| 강조 | 주목할 대상 하나만 짧게 | 지금 보라는 부분만 윤곽이 깜빡인다(1~2회) |
| 값 연동 | 슬라이더 값이 바뀌면 그림·수치가 같이 바뀐다 | 질량 슬라이더 → 무게 수치와 화살표 길이 |
| 궤적·잔상 | 움직인 길을 남겨 속도·방향 변화를 보이게 | 공이 지나간 길 표시 |

## 3. 재생 조작 (모든 움직임 공통)

- 재생 속도 버튼 **느리게 / 보통 / 빠르게**. 처음은 느리게로 시작한다.
- **일시정지 / 다시 재생** 버튼. 학생이 놓친 부분을 다시 볼 수 있어야 한다.
- 단계가 있는 움직임은 **한 단계씩 앞으로 / 뒤로**(→ ← 키, 버튼)가 된다.
- 자동으로 끝없이 반복하지 않는다. 한 번 재생하고 마지막 장면에서 멈추게 하거나, 입자 운동처럼 상태가 계속되는 것은 버튼으로 멈출 수 있게 한다.
- 마지막 장면(결론이 보이는 상태)을 화면에 남겨 둔다. 학생이 학습지에 옮겨 적는 시간이 필요하다.
- 예측 → 확인 활동: 학생이 예측을 적기 전에는 결과 재생 버튼을 누를 수 없게 하지 않는다(막지 않는다). 다만 화면에 "예측 먼저" 같은 안내 문구는 쓰지 않는다.

## 4. 물리·내용 정확성

- 움직임은 개념을 정확히 보여야 한다. 보기 좋게 만들려고 물리를 바꾸지 않는다.
- 공기 저항·마찰이 있는 장면은 물체가 결국 멈춘다. 교과서 상황(이상)과 실제를 비교하게 할 때만 토글로 둘을 보인다.
- 화면 밖으로 나가는 물체는 순간이동시키지 않고 화면(카메라)이 따라간다. 궤적을 남긴다.
- 화살표가 겹쳐 하나만 보이는 각도(0°, 180° 등)는 살짝 어긋나게 그린다.
- 입자 수, 속도 비율, 거리 비율은 개념에 맞는 방향이어야 한다(예: 온도가 2배가 되어도 입자가 눈으로 따라갈 수 없을 만큼 빨라지면 안 된다). 비율을 줄여 보여 줄 때는 초안에 "축척 변경"이라고 적는다.
- 교과서 그림과 같은 색·배치·기호를 쓴다. 학생이 교과서와 화면을 같은 것으로 알아본다.
- 교과서에 없는 현상·수치를 움직임으로 만들어 보여 주지 않는다.

## 5. 성능 (학생 기기: 터치 노트북, 렉, 약한 와이파이)

- 단일 HTML 파일에 모두 넣는다. 외부 라이브러리·CDN·외부 이미지에 의존하지 않는다. (포털 사이트의 라이브러리와는 별개다. 수업자료와 시뮬레이션 파일은 인터넷이 느려도 열려야 한다.)
- 그리기는 **SVG, CSS(transform·opacity), 가벼운 canvas**를 쓴다. 한 장면 입자 수는 기기가 버티는 만큼만(보통 수십~200개 이내) 정하고, 줄이는 쪽으로 정한다.
- `requestAnimationFrame` 하나로 돌리고, **그 그림이 화면에 보일 때만** 실행한다(수업자료는 세로 스크롤이라 IntersectionObserver로 본다). 화면에서 벗어나면 멈춘다.
- 프레임이 떨어질 때를 대비해 시간(dt) 기준으로 움직여서, 느린 기기에서도 속도가 같아 보이게 한다.
- 그림자 효과·블러·큰 그라데이션을 움직이는 요소에 쓰지 않는다.
- 학생 화면에서 터치 조작이 되고, 버튼은 손가락으로 누르기 쉬운 크기여야 한다.
- 움직임 줄이기 설정(`prefers-reduced-motion`)이 켜진 기기는 자동 재생을 멈추고 단계 버튼으로 보게 한다.

## 6. 디자인

- 색은 `디자인_규칙.md`를 따른다. 화면 틀(단추·카드·글자)은 검정·회색, 누르는 것과 고른 것만 검정이다. 그림 안에서 움직이는 대상을 강조할 때는 교과서 색이나 주황(#FFB340)을 쓰고, 비교하는 두 대상은 색 하나와 회색으로 나눈다. 예전 파란 강조색(#0066CC)은 쓰지 않는다.
- 스크롤에 맞춰 움직이는 그림(표지 별 자취, 정리 탭, 하늘 카드)은 `디자인_규칙.md` 5절. 예상 문항의 답을 보여 주는 움직임은 시뮬레이션 뒤에만 둔다.
- 움직임은 부드럽게(ease-in-out), 한 번에 하나만 움직이게 해서 시선이 갈 곳을 하나로 한다.
- 움직이는 그림 안의 글자(라벨, 수치)도 읽을 수 있는 크기로 하고, 움직일 때 글자가 도형에 가려지거나 잘리지 않는지 극단값(최소·최대·각도 0/90/180/270°)에서 확인한다.

## 7. 초안에 적는 방법

`작업규칙/초안_템플릿.md`의 쪽별 내용에 `모션` 항목이 있다. 움직임이 필요한 쪽마다 아래를 적는다.

- 무엇이 움직이는가: <대상>
- 어떻게 움직이는가: <방향·순서·속도 변화>
- 무엇을 이해시키려는가: <한 문장>
- 시작: <자동 / 클릭 / 슬라이더 조작>
- 단계: <단계가 있으면 1단계, 2단계 …>
- 마지막 장면: <멈춰 있을 때 화면에 남는 모습>
- 조작: <속도 버튼 / 일시정지 / 슬라이더 / 드래그>
- 비교: <나란히 비교하는 두 상태가 있으면>

움직임이 필요 없는 쪽은 "해당 없음"이라고 쓴다.

## 8. 구현 검수 (Claude Code)

- Playwright로 각 움직임을 실제로 재생해 스크린샷을 찍고, 첫 장면·중간 장면·마지막 장면을 눈으로 확인한다.
- 속도 버튼 3단계, 일시정지, 다시 재생, 한 단계씩 이동이 모두 동작하는지 확인한다.
- 다른 쪽으로 넘어갔을 때 움직임이 멈추는지 확인한다.
- 입자 수를 최대로 해서 렉이 없는지 확인한다.
- 물리가 교과서와 어긋나지 않는지 확인하고, 어긋나면 고치지 말고 보고한다.
